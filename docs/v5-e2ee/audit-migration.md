# 監査連携の移行ガイド — 代理閲覧 → スナップショット送信

E2EE 化 (v5.0, Epic [#84](https://github.com/nananek/iikanji-kakeibo/issues/84)) に伴い、
監査連携は**旧リアルタイム代理閲覧**から**非同期スナップショットワークフロー**へ
全面移行しました ([#112](https://github.com/nananek/iikanji-kakeibo/issues/112))。

本ガイドは、旧方式 (`AuditGrant` の代理閲覧) を利用していた被監査者 (owner) と
監査者 (auditor) 向けに、何が変わり何をすればよいかをまとめたものです。

---

## なぜ変わったのか

E2EE 化によりサーバは帳簿の平文を一切持たなくなりました。旧方式は「監査者が
ログインして被監査者になりすまし、サーバが復号・描画した帳簿をリアルタイム閲覧
する」仕組みでしたが、**サーバが平文を持たない構成ではこれは成立しません**。

そこで「税務顧問が顧客から資料を受け取って確認し、修正案を返す」という本来の
監査の在り方に沿った、**非同期スナップショット方式**へ移行しました。

---

## 新しいワークフロー

```
owner                                   auditor
  │  ① スナップショットを生成             │
  │    (ローカルで MK 復号 → 監査者の      │
  │     公開鍵で HPKE 暗号化)              │
  │ ──────── 送信 (AuditPackage) ───────▶ │
  │                                        │  ② 自分の秘密鍵で復号して監査
  │                                        │  ③ 修正案 / 差戻しを owner の
  │                                        │     公開鍵で暗号化して返信
  │ ◀──────── 返信 (AuditResponse) ─────── │
  │  ④ 復号してレビュー、採用 or 差戻し     │
```

- **サーバは暗号文 (ciphertext) を預かるだけ**で、owner / auditor いずれの平文も
  持ちません (HPKE: ephemeral X25519 + AES-256-GCM)。
- 同時編集はできません (スナップショットは不変コピー)。これは本来の税務顧問の
  在り方とも整合します。
- 権限レベル (Lv1 集計のみ / Lv2 税務科目のみ / Lv3 本人同等) は引き続き
  `AuditGrant` で管理し、Lv2 の公開科目は「公開科目」設定で選びます。

---

## 被監査者 (owner) の操作変更

| 旧方式 | 新方式 |
|--------|--------|
| 監査者にアクセスを付与 → 監査者がログインして閲覧 | 監査者にアクセスを付与 → **「送信」からスナップショットを暗号化送信** |
| Lv2 で「提出 / 提出取消」して閲覧可否を制御 | **提出フローは廃止**。送信した時点のスナップショットのみが監査者に渡る |
| 提出中は対象科目の仕訳が編集ロックされた | **編集ロックは廃止**。送信後も owner はいつでも自由に帳簿を編集できる (送信済みスナップショットは不変コピーのため影響しない) |

- 設定 → 監査アクセス管理から、各監査者の **「送信」** でスナップショットを送ります。
- Lv2 の場合は **「公開科目」** で監査者に見せる税務科目を選びます。

## 監査者 (auditor) の操作変更

| 旧方式 | 新方式 |
|--------|--------|
| クライアント一覧から **「切替」** して被監査者として閲覧 | クライアント一覧の **「受信したスナップショット」** から復号して閲覧 |
| サーバ描画の帳簿をそのまま編集 | 復号したスナップショットを監査し、**修正案 / 差戻しを暗号化して送信** |

- 「切替（旧）」によるリアルタイム代理閲覧は**廃止されました**。
- 監査者は自分の秘密鍵でスナップショットを復号し、修正案を構造化差分として
  送信できます (owner 側でワンクリック採用が可能)。

---

## 鍵の準備 (owner / auditor 共通)

非同期ワークフローは X25519 公開鍵ペアを使います。各ユーザーは初回に鍵ペアを
生成し、**相手の公開鍵フィンガープリントを TOFU (Trust On First Use) で確認・
ピン留め**します。IndexedDB をクリアした場合は再確認ダイアログが表示されます
(サイレントな再ピンニングは行いません)。

---

## 互換性に関する注意

- 旧 `auditor.switch` / `auditor.exit` ルート、`/settings/audit/<id>/submit` ・
  `/unsubmit` ルートは**削除されました**。
- 既存 DB に残る `AuditGrant.status = 'submitted'` レコードは新方式では参照されず、
  害もありません (該当カラムは後続のマイグレーションで物理削除予定)。
- `AuditGrant` / `AuditGrantAccount` テーブル自体は新ワークフローの権限管理・
  Lv2 公開科目管理に引き続き利用されます。
